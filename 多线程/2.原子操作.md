# 原子操作

原子类型允许原子访问，这意味着不需要额外的同步机制就可执行并发的读写操作。没有原子操作，递增变量就不是线程安全的，因为编译器首先要将值从内存加载到寄存器中，递增后再把结果保存回内存。另一个线程可能正在这个递增操作的执行过程中接触到内存，导致数据争用。

下为一个原子操作示例：

```cpp
bool atomic<T>::compare_exchange_strong(T& expected, T desired);
```

其实现了以下逻辑：

```cpp
if(*this == expected)
{
    *this = desired;
    return ture;
}else
{
    expected = *this;
    return false;
}
```

***
注意：

在C++20之前，对浮点类型使用 std::atomic，例如 atomic\<float> 和 atomic\<double> 提供了原子的读写操作，但没有提供原子的算术操作。C++20 为浮点原子类型添加了 fetch_add() 和 fetch_sub() 的支持。
***

大部分原子操作还可以接受一个额外参数，用于指定想要的内存顺序，如：

```cpp
T atomic<T>::fetch_add(T value, memory_order = memory_order_seq_cst);
```

C++标准还提供了memory_order可使用参数有： memory_order_relaxed、memory_order_consume、memory_order_acquire、memory_order_release、memory_order_acq_rel 和 memory_order_seq_cst。

## 原子智能指针

C++20通过\<memory> 引入对 atomic\<std::share_ptr\<T>> 的支持。早期C++标准是不支持的，因为share_ptr 不可拷贝。在多个线程中使用同一个atomic\<std::share_ptr\<T>> 示例时，即使调用非const 的share_ptr 方法也是线程安全的，但注意在share_ptr 所指的对象上调用非const 方法仍然不是线程安全的，需要手动同步。

## 原子引用

C++20引入了std::atomic_ref。即使使用相同的接口，它与std::atomic 基本相同，但是使用的是引用，而atomic 总是拷贝提供给他的值。

### 使用示例

对于以下会导致数据争用的函数：

```cpp
void increment(int& counter)
{
	for (int i {0};i<100;++i)
	{
		++counter;
		std::this_thread::sleep_for(std::chrono::microseconds(1));
	}
}
int main()
{
	int counter{ 0 };
	std::vector<std::thread> threads;
	for (int i {0};i<10;++i)
	{
		threads.emplace_back(std::thread{ increment, std::ref(counter) });
	}

	for (auto&t : threads)
	{
		t.join();
	}
	std::cout << "Result = " << counter << std::endl;
	
}
```

我们使用原子操作有如下几种解决方法：

```cpp
void increment(std::atomic<int>& counter)
{
	for (int i {0};i<100;++i)
	{
		++counter;
		std::this_thread::sleep_for(std::chrono::microseconds(1));
	}
}
int main()
{
	std::atomic<int> counter{ 0 };
	std::vector<std::thread> threads;
	for (int i {0};i<10;++i)
	{
		threads.emplace_back(std::thread{ increment, std::ref(counter) });
	}

	for (auto&t : threads)
	{
		t.join();
	}
	std::cout << "Result = " << counter << std::endl;
}
```

或者通过原子引用：

```cpp
void increment(int& counter)
{
	std::atomic_ref<int> atomicCounter{ counter };
	for (int i {0};i<100;++i)
	{
		++atomicCounter;
		std::this_thread::sleep_for(std::chrono::microseconds(1));
	}
}
int main()
{
	int counter{ 0 };
	std::vector<std::thread> threads;
	for (int i {0};i<10;++i)
	{
		threads.emplace_back(std::thread{ increment, std::ref(counter) });
	}

	for (auto&t : threads)
	{
		t.join();
	}
	std::cout << "Result = " << counter << std::endl;
}
```

但这里同时引入一个性能问题，我们应该试着最小化同步次数，包括原子操作和显式同步，因为这会降低性能。

```cpp
void increment(int& counter)
{
	int result{ 0 };
	for (int i {0};i<100;++i)
	{
		++result;
		std::this_thread::sleep_for(std::chrono::microseconds(1));
	}
	counter += result;
}
```
